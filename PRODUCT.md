# Product

## Register

product

## Users

HyperOps is used by operations and platform engineers who manage Jenkins, GitLab, monitoring, notifications, and automation workflows during daily operational work. Users need dense but readable screens that help them make changes confidently, inspect state quickly, and recover from failed operations without guessing.

## Product Purpose

HyperOps centralizes operational administration for internal engineering platforms. Success means the console clearly separates configured intent from external platform reality, exposes the next useful action, and keeps high-risk operations such as deployments, rule sync, and credential changes explicit.

## Brand Personality

Calm, precise, work-focused. The interface should feel like a modern operations console: direct language, low visual noise, clear status, and consistent controls.

## Anti-references

Avoid marketing-style dashboards, decorative gradients, oversized hero sections, heavy bordered cards, nested cards, and raw technical formats as the default experience. Avoid mixed Chinese/English operational copy unless the term is a product name or command.

## Design Principles

1. Lead with the operator task, not system internals.
2. Separate local configuration from external platform reality.
3. Make destructive, sync, and deployment actions explicit and reversible where possible.
4. Prefer compact shared components over one-off page styling.
5. Show raw YAML, logs, and JSON as advanced views, not the primary workflow.

## Accessibility & Inclusion

Use readable contrast, predictable keyboard-focus states, standard form controls, and reduced visual clutter. Motion should only communicate state changes and must not block task flow.
