# Product

## Register

product

## Users

HyperOps is used by operations and platform engineers who manage Jenkins, GitLab, monitoring, notifications, and automation workflows during daily operational work. Administrators also configure integrations, inspect system state, and review access. Users need dense but readable screens that help them make changes confidently, inspect state quickly, and recover from failed operations without guessing.

## Product Purpose

HyperOps centralizes operational administration for internal engineering platforms, including Jenkins, GitLab, object storage, accounts, access control, and execution records. Success means the console clearly separates configured intent from external platform reality, exposes the next useful action, and keeps high-risk operations such as deployments, rule sync, and credential changes explicit.

## Brand Personality

Calm, precise, work-focused. The interface should feel like a modern operations console: direct language, low visual noise, clear status, and consistent controls. It should be quiet when everything is healthy, explicit when attention is needed, and honest about unavailable or unconfigured resources.

## Anti-references

Avoid marketing-style dashboards, decorative gradients, oversized hero sections, excessive glassmorphism, heavy shadows, heavy bordered cards, nested cards, oversized rounded surfaces, and dashboards that put every possible metric on the first screen. Avoid mixed Chinese/English operational copy unless the term is a product name or command. Do not represent an unconfigured integration as a service failure.

## Design Principles

1. Lead with the operator task, not system internals.
2. Separate local configuration from external platform reality.
3. Make destructive, sync, and deployment actions explicit and reversible where possible.
4. Prefer compact shared components over one-off page styling.
5. Show raw YAML, logs, and JSON as advanced views, not the primary workflow.
6. Use hierarchy and whitespace before decoration.
7. Make state and consequences explicit in words, not color alone.
8. Keep common actions predictable across management and workspace surfaces.
9. Reveal secondary detail progressively so dense information stays scannable.

## Accessibility & Inclusion

Target WCAG 2.1 AA. Use readable contrast, predictable keyboard-focus states, standard form controls, and reduced visual clutter. Preserve labels for icon-only controls, state communication beyond color, responsive layouts at narrow widths, and reduced-motion behavior. Motion should only communicate state changes and must not block task flow.
