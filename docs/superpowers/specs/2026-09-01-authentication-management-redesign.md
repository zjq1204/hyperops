# 认证管理页面重设计

## 目标

将现有“登录与身份源”改为成熟后台常用的“认证管理”，首屏只回答平台有哪些认证方式、作用范围和当前状态，不在列表页直接编辑配置。

## 信息架构

- 用户管理下只保留一个“认证管理”入口。
- 认证管理首页使用单表列表，展示本地账号、LDAP / AD 实例以及每个企业对应的飞书认证。
- 飞书配置进入独立页面，一个企业只对应一个飞书应用。
- LDAP 继续使用现有完整配置页，旧地址保留兼容，但不再作为独立侧边栏菜单。
- 对象存储接入页跳转到对应企业的飞书配置页。

## 列表字段

- 认证方式：实例或企业飞书名称。
- 类型：内置、LDAP / AD、OAuth 2.0。
- 作用范围：全平台或“企业 · 对象存储”。
- 状态：已启用、已停用、待配置、待验证、验证失败、已验证。
- 操作：查看用户或进入对应配置页。

## 权限

- 认证管理首页沿用 `admin_users` 权限，普通用户管理员仍可管理 LDAP。
- 对象存储模块启用且当前用户为超级管理员时，列表才展示企业飞书来源。
- 飞书详情页继续要求超级管理员、`admin_object_storage` 权限和对象存储模块开关。

## 交互与状态

- 列表加载时显示统一加载状态。
- 没有 LDAP 或企业飞书时仍保留本地账号行，不使用空白页。
- 飞书详情页内选择企业；切换企业时加载该企业唯一的飞书应用配置。
- 密钥只写不读，修改后需要重新验证。
- 页面在桌面和移动端不得出现字段或操作重叠。
