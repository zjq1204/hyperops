# 探测配置中心设计规格

## 1. 背景

当前“探测目标”页面同时展示探测目标、Prometheus 汇总、治理问题、
blackbox-exporter 节点和 HTTP SD 接入配置。不同使用频率和不同技术层级的内容被平铺在一个页面中，
导致主任务不明确，并且“配置状态”“Prometheus 是否获取配置”“探测是否成功”容易被混为一谈。

本次改造将页面定位为探测配置中心。它负责维护探测目标，以及确认目标是否已被 Prometheus 获取；
它不承担完整的监控结果分析职责。

## 2. 产品目标

1. 用户进入页面后可以立即找到、新增、编辑、停用或删除探测目标。
2. 用户可以明确区分目标配置是否启用、配置是否已生效、最近一次探测是否异常。
3. 低频的探针节点和 Prometheus 接入配置仍可访问，但不干扰目标管理。
4. 新增目标只展示完成当前任务所必需的字段，标签等可选配置按需展开。
5. 沿用现有 HTTP SD 数据流，不要求用户在每次新增 blackbox-exporter 后手工修改 Prometheus 配置文件。

## 3. 非目标

- 不在本页面实现时序趋势、可用率报表或完整故障分析。
- 不在第一版实现探针节点负载均衡、健康感知调度或自动故障转移。
- 不在第一版修改 HTTP SD 的 Prometheus 配置结构。
- 不新增独立的 blackbox 实例主菜单。

## 4. 信息架构

页面采用两级配置工作台。

### 4.1 一级：探测目标

默认页面只包含以下区域：

1. 页面标题和操作区：`探测目标`、`基础配置`、`新增探测`。
2. 筛选区：关键词、探测类型、配置状态、生效状态。
3. 目标表格：目标、类型、探针节点、标签、配置状态、生效情况、操作。

移除页面顶部的大块 Prometheus 统计卡片。Prometheus 连接异常时，在列表上方显示一条可恢复的行内提示，
内容必须说明原因，并提供“重试”或“前往基础配置”。

治理问题不再独立展示为黄色标签区。与具体目标有关的问题并入该目标的“生效情况”；
无法匹配具体目标的系统级问题只在“基础配置”入口上显示提醒标记。

### 4.2 二级：基础配置

点击“基础配置”进入独立视图，不使用与目标列表平级的页签。该视图包含：

- 探针节点：节点名称、地址、来源、启停状态和维护操作。
- Prometheus 接入：连接状态、Token 状态、HTTP SD 地址、YAML 预览与复制。

基础配置使用独立子路由 `/management/monitoring/probes/settings`，并提供明确的“返回探测目标”。
刷新页面后保留当前视图，浏览器返回时恢复目标列表的筛选和滚动位置。

## 5. 目标列表

### 5.1 筛选

- 关键词支持匹配目标地址、探针节点名称和标签值。
- 探测类型为下拉框：全部、HTTP、TCP、ICMP。
- 配置状态为下拉框：全部、已启用、已停用。
- 生效状态为下拉框：全部、已生效、待拉取、采集异常、配置不完整、无法确认。
- 筛选条件应写入 URL query，返回页面时保留。

### 5.2 表格

- 目标地址是每行的第一视觉重点，类型使用独立窄列和紧凑文字标签。
- 探针节点显示名称；地址作为次要信息，不占用主要视觉层级。
- 标签默认最多显示两个，其余以 `+N` 表示，完整内容在详情中查看。
- 配置状态只显示“已启用”或“已停用”。
- 生效情况由一个主状态和一行必要说明组成，不叠放多个状态徽标。
- 行操作只保留一个“更多”菜单，包含编辑、启用/停用和删除。
- 点击非交互区域打开右侧详情抽屉。

### 5.3 生效状态定义

| 状态 | 判断条件 | 用户说明 |
| --- | --- | --- |
| 配置不完整 | 未绑定可用探针节点，或节点已停用 | 选择可用探针节点后才能生效 |
| 待拉取 | 配置已启用且完整，但 Prometheus 快照中未发现目标 | 等待 Prometheus 获取配置 |
| 已生效 | Prometheus 已发现目标，且最近探测成功 | 配置已生效 |
| 采集异常 | Prometheus 已发现目标，但最近探测失败 | 展示最近错误，并提供查看详情 |
| 无法确认 | Prometheus 未连接或快照读取失败 | 无法读取 Prometheus 状态，可重试 |

“已停用”属于配置状态，不参与生效状态筛选；当目标停用时，生效情况显示短横线，避免重复表达。

## 6. 新增和编辑探测

新增探测使用单个模态框，不采用多步骤流程，因为必填字段数量较少。

### 6.1 必填区

1. 探测类型：HTTP、TCP、ICMP 分段选择。
2. 目标地址：根据类型显示示例并校验格式。
3. 探针节点：从已启用节点中选择。

当只有一个可用节点时自动选中；有多个节点时必须由用户确认，不显示当前后端并不支持的“自动调度”。
没有可用节点时，表单不允许提交，并提供“新增探针节点”入口。完成节点创建后返回表单并保留已填写内容。

### 6.2 可选区

- 默认启用目标。
- “更多设置”内包含地域、环境、团队、服务、探测范围和关键目标标记。
- 可选字段不得预填带业务含义的伪默认值；未填写时不写入标签。

### 6.3 校验和反馈

- HTTP 目标必须是完整的 `http://` 或 `https://` URL。
- TCP 目标使用 `host:port`。
- ICMP 目标使用主机名或 IP，不接受协议和端口。
- 错误显示在对应字段下方，提交失败时聚焦第一个错误字段。
- 保存成功后关闭弹窗并提示“配置已保存，等待 Prometheus 拉取”。
- 保存请求期间禁用提交按钮并显示加载状态，防止重复创建。

## 7. 详情抽屉

详情抽屉用于查看和诊断，不承载新增流程。内容包括：

- 基本配置：类型、目标、探针节点、启停状态。
- 标签：完整键值列表。
- 生效信息：Prometheus 是否发现、最近检查时间、最近错误。
- HTTP SD 信息：最终使用的 blackbox 地址。

抽屉底部提供“编辑”和“启用/停用”。删除放在更多菜单中，并需要二次确认。

## 8. 基础配置交互

### 8.1 探针节点

- 安装 blackbox-exporter 成功后自动注册的节点显示来源“自动安装”。
- 手工添加的节点显示来源“手动添加”。
- 节点列表显示是否启用，以及被多少个目标使用。
- 停用或删除被目标使用的节点前，明确提示受影响目标数量。
- 第一版不展示“在线”状态，除非后端提供经过实时健康检查的可靠数据。

### 8.2 Prometheus 接入

- 默认只显示连接状态、Token 是否已配置和 HTTP SD 地址。
- “管理 Token”打开 Token 弹窗，“查看配置”打开 YAML 弹窗，避免长代码块占满基础配置页面。
- 重新生成 Token 必须提示旧 Token 将立即失效。
- 新 Token 只完整显示一次，并提供复制按钮。
- YAML 预览和复制是同一份后端生成内容，复制成功必须有明确反馈。

## 9. 数据流

1. 用户保存目标后，目标进入数据库。
2. HTTP SD 接口立即返回所有已启用且绑定了已启用探针节点的目标。
3. Prometheus 按配置的刷新周期获取 HTTP SD 数据。
4. 后端通过 Prometheus target 快照匹配 `type + target`，计算生效状态。
5. 前端刷新列表时展示配置状态和计算后的生效状态。

如果目标已启用但探针节点不可用，HTTP SD 不应静默下发缺少 `blackbox_address` 的记录；
后端应返回可识别的“配置不完整”状态供管理 API 使用。

## 10. 错误与空状态

- 无目标：显示“还没有探测目标”和“新增探测”，不展示 Prometheus 统计或无意义的零值。
- 无探针节点：说明需要先准备 blackbox-exporter 节点，并提供创建入口。
- Prometheus 未连接：目标配置仍可维护，但生效状态显示“无法确认”。
- 列表请求失败：保留页面框架和筛选，显示原因及重试按钮。
- 单个目标状态异常：只影响对应行，不把整个页面切换成错误状态。

## 11. 视觉与响应式规则

- 采用克制、数据密集的运维工具风格，保持与现有管理后台一致。
- 页面只有“新增探测”一个主要按钮；基础配置、刷新等为次要操作。
- 状态不能只依赖颜色，必须同时有文字或图标。
- 桌面端使用表格；窄屏改为按目标分组的列表，不产生横向滚动。
- 所有按钮和菜单项具备清晰的悬停、焦点、加载和禁用状态。
- 不使用装饰性卡片、重复说明、大面积彩色状态区或多层嵌套卡片。

## 12. 实施边界

前端应将当前体量过大的 `Probes.vue` 拆分为目标列表、目标表单、目标详情、基础配置和状态映射等局部组件或组合函数，
但不进行监控模块之外的公共组件重构。

后端优先复用现有目标、节点、HTTP SD 和 Prometheus 汇总接口。仅在现有接口无法稳定提供以下数据时扩展序列化结果：

- 统一生效状态及原因。
- 探针节点关联目标数量。
- 配置不完整的明确原因。

## 13. 验收标准

1. 默认首屏只展示探测目标管理，不再平铺节点和 Prometheus 配置。
2. 用户能在一次弹窗中完成目标创建，并获得明确的格式校验和保存反馈。
3. 目标列表不会同时堆叠配置、治理和 Prometheus 多个状态徽标。
4. 已保存但尚未被 Prometheus 获取的目标准确显示“待拉取”。
5. Prometheus 不可用时仍可维护配置，页面不会整体不可用。
6. 节点和 Prometheus 接入均可从“基础配置”进入并明确返回。
7. Token、YAML 复制和重新生成流程均提供可靠反馈与风险提示。
8. 桌面和移动视口下无内容重叠或无意义横向滚动。
