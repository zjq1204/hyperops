# 对象存储凭证一期正式设计

日期：2026-09-01
状态：待书面评审
版本：2.0
英文版：`docs/superpowers/specs/2026-08-31-object-storage-credentials-phase-one-design.md`

## 1. 目标与决策摘要

在 HyperOps 中提供平台级对象存储自助服务。用户通过飞书登录 HyperOps，在自己的
对象存储工作区申请和管理 Bucket、访问密钥及申请记录；平台管理员在管理侧配置阿里云
连接、Bucket 默认策略、配额和资源状态。

本版本彻底移除对象存储产品中的“企业”“租户”“企业接入”概念：

- 平台只配置一个飞书应用。
- 平台只配置一个启用中的阿里云 OSS 资源池。
- Bucket、RAM 用户、AK/SK 和申请记录直接归属 HyperOps 用户。
- 飞书和对象存储配置分别是平台唯一配置，不通过企业选择进入。
- LDAP、本地账号和飞书账号仍是独立身份，不按姓名、邮箱或手机号自动合并。

一期采用方案 B：以平台级单实例模型替换旧企业模型。当前尚未上线且没有真实对象存储
数据，不保留旧模型兼容层，不提供 V1/V2 并行接口。

## 2. 一期范围

### 2.1 包含

- 一个平台级飞书自建应用。
- 一个平台级阿里云 OSS 资源池。
- 飞书 OAuth 登录和首次登录即时创建本地用户。
- 飞书用户与一个本地组的绑定；组继续通过现有角色配置工作台和控制台权限。
- 用户批量申请多个 Bucket，每个 Bucket 单独填写业务信息。
- 一个 HyperOps 用户对应一个专属阿里云 RAM 用户。
- 每个用户默认最多 5 个正常或处理中 Bucket，管理员可调整用户配额。
- 同一 RAM 用户下最多两组有效 AK/SK；所有密钥都可以访问该用户的全部 Bucket。
- AK/SK 一次性交付、禁用、启用、轮换和单把吊销。
- Bucket 释放、恢复、待删除和删除受阻处理。
- 管理员配置和修改 Bucket 的平台默认值及单个 Bucket 的允许配置。
- 异步云操作、幂等、重试、失败恢复和审计日志。

### 2.2 明确不包含

- 多企业、多租户或企业选择。
- 多个启用中的飞书应用或对象存储资源池。
- 华为云或其他云厂商。
- 人工审批流程。
- 定时飞书同步、飞书事件通知和通知对象配置。
- TOTP、KMS、OpenBao 或外部 Secret 管理系统。
- 离线审计归档。
- 跨用户共享或移交 Bucket。
- 普通用户修改 Bucket ACL、Policy、公网访问、Region、存储类型、加密、版本控制或生命周期。
- 公共读写 Bucket。
- 自动按用户停用状态删除云资源。

## 3. 领域模型

```text
平台
├─ PlatformFeishuConfig（唯一）
│  └─ FeishuIdentity → HyperOps User
└─ PlatformObjectStorageConfig（唯一）
   └─ CloudResourcePool（阿里云，唯一启用）
      └─ HyperOps User
         ├─ CloudIdentity（一个 RAM 用户）
         ├─ AccessKey（最多两组有效）
         ├─ Bucket（多个）
         └─ ApplicationBatch
            └─ ApplicationItem（每个 Bucket 一项）
```

### 3.1 平台配置

`PlatformFeishuConfig`：平台唯一飞书应用配置，包括 App ID、加密后的 App Secret、
OAuth 回调地址、验证状态、启用状态和绑定的本地组。飞书应用的可见范围决定准入用户，
本地组决定登录后得到的角色权限。

`PlatformObjectStorageConfig`：平台唯一对象存储配置，包括资源池、命名模板、默认
Bucket 配额、凭证领取时限、审计保留时长、平台开关和默认 Bucket 安全策略。

`CloudResourcePool`：阿里云账号 ID、Region、管控 AK/SK 密文、凭证指纹、验证状态和
启用状态。云厂商和账号 ID 在创建真实资源后锁定；更换管控凭证必须验证仍属于同一账号。

### 3.2 用户资源

`FeishuIdentity` 保存飞书 open ID、可选 union ID、展示名、部门快照、来源标识和状态，
并关联 HyperOps 用户。只有来源为飞书的身份会被手动同步处理。

`CloudIdentity` 直接关联 HyperOps 用户和资源池，保存 RAM 用户 ID、用户名及状态。平台
保证同一用户在一期唯一资源池中最多有一个 CloudIdentity。

`Bucket` 直接关联 HyperOps 用户、资源池和 CloudIdentity，保存业务名称、最终名称、用途、
项目、环境、备注、Region、模板版本、云端标识、配置快照和状态。Bucket 名称和 Region
创建后不可直接修改。

`AccessKey` 关联 CloudIdentity，保存加密后的 AK/SK、指纹、后四位、云端状态、本地状态、
创建时间和同步时间。标准接口永不返回密文或明文。

### 3.3 申请与审计

`ApplicationBatch` 表示一次提交，保存申请人、幂等键、批次状态、汇总计数、当前阶段和
安全错误摘要。

`ApplicationItem` 表示批次中的一个 Bucket，保存业务字段、最终名称、独立状态、当前阶段、
重试次数、错误码和关联 Bucket。每个子项独立成功、失败、重试或取消。

`ApplicationAttempt` 和 `ApplicationEvent` 保存执行次数、Celery 任务信息、技术阶段、
结果和不可变状态变化记录。

`DeliveryTicket` 保存一次性交付 Token 摘要、过期时间、消费时间和状态。Token 只在创建
时返回给受限的用户流程，成功领取后立即消费。

`AuditEvent` 是不可修改的审计事件，保存操作者 ID 和名称快照、动作、目标、原因、结果、
IP、request ID 和时间。审计记录不能依赖用户删除而级联删除。

## 4. 身份认证与授权

### 4.1 飞书登录

1. 登录页提供“飞书登录”，不提供企业选择。
2. 后端使用平台唯一飞书配置生成一次性、短时有效的 OAuth state。
3. 回调只信任服务端 state、配置的 App ID 和飞书服务端返回结果。
4. 按 `open_id` 关联 `FeishuIdentity`；不使用姓名、邮箱或手机号自动合并。
5. 首次登录成功后创建密码不可用、非 staff、非 superuser 的 HyperOps 本地用户。
6. 登录只创建本地用户和 FeishuIdentity，不创建 RAM 用户、Bucket、Policy 或密钥。
7. 用户登录后获得绑定本地组对应的角色、工作台权限和控制台权限。

LDAP 和本地账号留在各自的用户管理与认证配置中，不放入飞书配置页面。飞书手动同步先
展示变更预览，管理员确认后执行；只处理飞书来源用户，不影响 LDAP 或本地用户。

### 4.2 对象存储权限

- 普通用户只能访问和操作自己名下的 Bucket、密钥和申请记录。
- 平台管理员可以查看和管理全平台资源。
- 不新增对象存储专属管理员角色，使用现有平台管理员权限。
- 菜单隐藏不能替代后端接口鉴权；跨用户对象统一返回不存在。
- 用户被停用或删除时，只标记待处理风险，不自动删除云资源。
- 本地用户仍有关联云资源时禁止物理删除；管理员先处理资源，再删除本地用户。

## 5. 首次申请与批量申请

### 5.1 用户填写

用户可在一张申请单中增加多个 Bucket 项。每项包含：

- 业务名称（必填）。
- 用途（必填）。
- 项目（选填）。
- 环境：开发、测试或生产（选填时使用平台默认值）。
- 备注（选填）。

用户不填写云账号、Region、ACL、Policy、存储类型、加密、版本控制或生命周期。

提交前展示每项最终 Bucket 名称、名称校验、预计配额占用和批次汇总。配额校验按整批执行，
不允许提交超过剩余额度的批次。

### 5.2 执行顺序

首次申请固定按以下顺序执行：

1. 创建或确认该用户的 RAM 用户。
2. 创建第一组 AK/SK。
3. 逐项创建 Bucket。
4. 按该用户当前全部有效 Bucket 集合对账 RAM Policy。
5. 保存加密凭据并创建交付票据。

后续新增 Bucket 复用 RAM 用户和现有密钥，只创建 Bucket 并重新对账 Policy；新增 Bucket
不会创建新的 RAM 用户或密钥。

至少一个 Bucket 成功并完成授权后，用户可以领取 AK/SK。全部 Bucket 失败或仍在重试时，
暂不允许领取。全部失败后用户取消，删除未交付密钥和无资源 RAM 用户；部分成功后取消失败
项，只保留成功资源和共享密钥。

### 5.3 子项状态

批次状态根据子项汇总：`等待中`、`处理中`、`已完成`、`部分完成`、`失败`、`已取消`、
`需人工处理`。

子项状态包括：`等待中`、`创建中`、`成功`、`失败`、`取消`、`释放中`、`待删除`、
`删除受阻`。技术阶段单独存储，不在用户列表中堆叠展示。

批次列表使用“处理中 2 个、已完成 3 个、失败 1 个”的汇总，不使用“成功 3 次”、任务
编号或 `#` 号作为产品主信息。操作使用固定入口“查看详情”“重试失败项”“取消此项”。

## 6. 命名与配额

### 6.1 Bucket 命名

用户只填写业务名称，系统使用管理侧模板生成最终名称并附加 8 位小写字母和数字随机后缀，
例如：`hyperops-monitoring-prod-a7k3m9qx`。

最终名称规则：

- 长度 3 至 63 个 ASCII 字符。
- 仅允许小写字母、数字和连字符。
- 必须以字母或数字开头和结尾。
- 前端实时显示最终名称和可用长度；后端再次校验。
- 超长直接禁止提交，不自动截断。
- 创建前检查本地记录和云端状态。
- 云端返回名称冲突时自动重新生成后缀，最多重试 3 次。
- 仍冲突则该子项失败，不授予权限，允许单独重试。

随机后缀不是唯一保障。最终以云端原子创建结果为准，避免并发请求之间的检查竞态。

### 6.2 配额

平台默认每用户 5 个 Bucket，管理员可修改默认值或为单个用户设置覆盖值。

- 正常、等待创建、创建中、等待重试的 Bucket 占用配额。
- 释放执行中的 Bucket 在完成进入待删除前占用配额。
- 待删除、已释放、删除受阻的 Bucket 不占配额。
- 最终取消的失败项释放预占配额。
- 批量提交前一次性校验剩余额度。
- 并发申请锁定用户配额记录后检查并预占，防止超配。
- 恢复待删除 Bucket 前重新检查配额，失败则不能恢复。

## 7. Bucket、密钥和管理员配置

### 7.1 Bucket 权限

同一用户的所有 AK/SK 都可以访问该用户的全部 Bucket，RAM Policy 由当前有效 Bucket
集合生成。用户拥有完整对象操作权限，包括列表、读取、上传、覆盖、删除和分段上传；
不能创建或删除 Bucket，不能访问其他用户资源，不能授予第三方权限。

Bucket 默认私有。管理侧可将单个 Bucket 设置为“公共读”，必须填写原因、二次确认并
记录审计；一期不提供公共读写。ACL、Policy、公网访问、存储类型、加密、版本控制和生命
周期等配置均只允许管理侧操作。名称和 Region 属于创建时属性，不能编辑。

### 7.2 密钥

- 用户可以查看脱敏摘要并管理自己的密钥：禁用、启用、轮换、吊销。
- 吊销一把密钥不影响另一把密钥。
- 最多保留两组有效密钥。
- 只有一组密钥时，轮换创建第二组。
- 两组都存在时，按明确的轮换确认选择最早的一组或已禁用的一组先退出，再创建替代密钥；不静默选择。
- 在云厂商两把密钥上限下，轮换通过“先处理选中旧密钥、再创建新密钥”完成，始终保留剩余密钥。
- 删除旧密钥后新密钥创建失败，进入需人工处理，不再自动删除另一把密钥。

AK/SK 创建或轮换成功时完整展示一次，之后只显示脱敏信息。管理员查看完整密钥必须
填写原因并写入审计；一期暂不做 TOTP。

### 7.3 配置编辑与平台开关

管理侧设置分为连接配置、Bucket 默认配置、命名规则、配额与保留策略、平台开关。

- 管控 AK/SK 可轮换，但新凭证必须验证属于同一云账号且权限完整。
- 云厂商和阿里云账号 ID 创建真实资源后锁定。
- Region 修改只影响后续 Bucket，已有 Bucket 保留原 Region。
- 平台默认 ACL、存储类型、加密、版本控制、生命周期和命名模板只影响后续 Bucket。
- 单个已有 Bucket 支持管理侧异步修改云端支持的配置，失败保留原配置。
- “暂停新申请”不影响已有资源和用户查询。
- “暂停密钥操作”禁止新建、轮换和启用，但允许禁用和吊销。
- 不提供“一键停用全部对象存储资源”。
- 连接验证失败时自动阻止新申请和密钥签发，不自动改变已有云资源。

## 8. Bucket 释放与用户生命周期

用户释放 Bucket 前输入完整最终名称并二次确认。系统先检查对象、对象版本、删除标记和
未完成分段上传；非空时拒绝释放。

空 Bucket 释放后：

1. 立即从该用户 RAM Policy 移除，AK/SK 不能再访问该 Bucket。
2. Bucket 和数据保留 7 天，进入待删除，不占配额。
3. 7 天内可恢复，恢复前重新校验配额并重新授权。
4. 到期后空 Bucket 自动删除。
5. 非空 Bucket 不自动清空，进入删除受阻，等待用户清理或管理员明确处理。

管理员可对 Bucket 执行释放、恢复和立即删除；立即删除必须二次确认。管理员不通过普通
“停用对象存储”总开关处理资源。

用户停用或删除只产生风险标记。管理员在访问密钥和 Bucket 页面分别禁用/吊销密钥、释放/
删除 Bucket，最后再清理 RAM 用户。用户仍有关联云资源时，本地用户禁止物理删除。

## 9. 执行架构与失败恢复

新增独立 Django App `object_storage`，复用现有用户、角色、API、Celery、日志和前端框架。
云厂商适配器只暴露业务动作，不向上层暴露原始 SDK：

```text
validate_management_identity
find_or_create_personal_principal
create_owned_bucket
inspect_bucket_emptiness
delete_owned_bucket
reconcile_object_policy
list_access_keys
create_access_key
deactivate_access_key
activate_access_key
delete_access_key
update_bucket_configuration
```

API 只创建批次并返回 ID；云操作进入低并发对象存储队列。每次外部变更前读取云端实际
状态；用幂等键、数据库锁和资源标识防止重复创建。

- 网络、超时、限流、服务暂不可用：最多自动重试 3 次并指数退避。
- 配额、格式、归属、权限、加密、密钥数量和配置错误：不自动重试。
- 超时重试前按确定性 RAM 用户名、最终 Bucket 名称和 HyperOps 标识查询云端。
- Policy 失败时保留 RAM 用户和 Bucket，只重试授权对账，不重复签发密钥。
- AK/SK 创建成功但加密保存失败：尝试删除准确的密钥；无法确认删除结果则需人工处理。
- 管理员修改 Bucket 配置失败：保留原配置并提供固定“重试”动作。
- 部分批次失败不回滚成功项。

## 10. 密钥、日志与审计

App Secret、云管控凭证和用户 SK 使用数据库加密保存；一期不依赖 KMS、OpenBao 或新增
环境变量。采用基于 HyperOps `SECRET_KEY` 派生的模块密钥、随机 nonce 和带完整性校验的
认证加密。更换根密钥前必须运行重加密命令，解密失败不得降级为明文。

遵循 `docs/logging.md`：日志只记录 request ID、task ID、用户 ID、批次 ID、Bucket 名称、
阶段、耗时、错误类型和安全的云请求 ID。禁止记录完整 AK/SK、密文、App Secret、Authorization
请求头、交付 Token 或凭证接口请求体。

审计覆盖：飞书登录创建用户、同步预览和执行、申请提交、云资源创建、Policy 变更、密钥
签发/禁用/启用/轮换/吊销、一次性领取、管理员查看、Bucket 配置修改、释放/恢复/删除、
重试、取消和人工处理。审计默认保留一个月，保留时间可在平台设置中配置；一期不做离线归档。

## 11. 页面信息架构

### 11.1 用户侧

```text
我的对象存储
├─ 概览
├─ Bucket
├─ 访问密钥
└─ 申请记录
```

概览展示配额、RAM 用户状态、密钥摘要、最近申请和明确的主操作。新建申请使用独立页面，
不是承载复杂表单的大弹窗。Bucket 列表展示业务名称、最终名称、用途、环境、状态和固定
操作；访问密钥单独展示后四位、状态、创建时间和固定操作；申请记录展示批次汇总，执行阶段
和诊断只在详情页展开。

### 11.2 管理侧

```text
对象存储管理
├─ 概览
├─ 存储设置
├─ Bucket
├─ 访问密钥
├─ 申请记录
└─ 审计日志
```

不再出现“企业接入”“选择企业”“企业策略”。列表页以扫描和对比为优先，操作列统一使用
“查看”“管理”或固定三点菜单；状态不替代动作。长配置使用页面分组，紧凑详情可使用抽屉。

未配置或平台开关关闭时，用户侧只显示“对象存储尚未开放”和联系管理员提示，不展示申请表。
管理侧显示连接凭证、Region、命名模板、配额、保留策略和开关的检查清单。

## 12. API 与权限契约

所有路由位于 `/api/v1/object-storage/`。用户 API 包括概览、自己的 Bucket、批量申请、
申请详情、申请项重试/取消、密钥摘要、一次性领取、密钥管理和 Bucket 释放/恢复。

管理 API 包括平台配置、连接验证、Bucket 默认配置、用户配额、全平台 Bucket、RAM 用户、
密钥、申请记录、失败恢复、单密钥查看和审计查询。管理 API 仅允许现有平台管理员。

所有写操作支持幂等键；错误使用稳定领域错误码，不把云厂商异常原文直接返回给用户。用户
响应与管理响应使用不同 Serializer，敏感字段不会因复用序列化器泄漏。

## 13. 测试与验收

后端必须覆盖：平台配置单例、用户归属、飞书即时创建、不自动合并、组权限、配额并发、
批量部分成功、全部失败、取消和重试、随机命名和冲突重试、RAM 用户复用、Policy 精确对账、
密钥加密和一次性交付、两组密钥轮换失败恢复、释放/恢复/删除受阻、管理员与用户隔离、
公共读审计和日志脱敏。

前端必须覆盖：未配置空态、批量申请动态表单、最终名称预览、配额提示、批次汇总、固定动作、
失败项重试、密钥脱敏和管理侧配置保存/验证/失败恢复。

阿里云适配器用脱敏 fixture 做常规契约测试；测试账号补充上传、下载、覆盖、删除、跨用户
拒绝、Bucket 管理拒绝、密钥轮换和部分失败恢复验证。

## 14. 上线顺序

3. 实现飞书配置、组授权和即时用户创建。
4. 实现对象存储设置与连接验证。
5. 实现用户批量申请、RAM 用户、AK/SK 和 Bucket 编排。
6. 实现用户侧资源管理和固定动作体验。
